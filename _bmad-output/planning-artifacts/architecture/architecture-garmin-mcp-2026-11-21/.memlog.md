- (direction) Version directe avec hypothèses signalées. Livrer le cadrage d’architecture, la règle Git pour .env et les étapes Render dans la réponse. Le code et le déploiement sont hors de cette étape.
- (constraint) Application personnelle, Spring Boot avec MCP en lecture seule, accessible depuis ChatGPT web quand le Mac est éteint. Hébergement Render Free. Une clé Garmin personnelle existe déjà et sa valeur est hors du travail.
- (note) Le dépôt de départ contient le README et aucun dossier BMad. Les deux capacités et les conventions déjà discutées servent de référence pour le cadrage.
- (version) Pile d’amorçage proposée le 21 novembre 2026 : Java 21, Spring Boot 4.2.0, Spring AI 2.1.0 GA, Maven et Spring Security via le BOM Boot. La note de version et la référence Spring confirment la compatibilité.
- (assumption) AD-1 — Un monolithe en couches WebMVC, outils vers services d’analyse vers client Garmin, permet une livraison Docker unique. Le transport stateless évite de lier le fonctionnement aux sessions en mémoire de Render.
- (decision) AD-2 — Deux liaisons OAuth indépendantes. OAuth avec PKCE et découverte pour ChatGPT vers Spring, audience égale à l’URL MCP, vérification du JWT et du sujet du propriétaire avant accès Garmin. WorkOS AuthKit via CIMD est une hypothèse d’intégration vérifiée sur documentation, à éprouver avec ChatGPT réel.
- (decision) AD-3 — Spring transforme exclusivement la clé personnelle en jeton Garmin côté serveur. Un jeton transitoire en mémoire, une durée de vie bornée par Garmin, aucune donnée métier persistée.
- (decision) AD-4 — Les services d’analyse produisent les agrégats complets en lecture seule. La date de départ locale, la période, le rattachement au réveil, la marche, les jours sans séance et les absences de données conservent les conventions discutées.
- (decision) AD-5 — Un Web Service Render Free avec Docker, écoute sur PORT, HTTPS Render, health check minimal et configuration d’exécution distincte du build. Francfort est une hypothèse de région. La branche main est la source de déploiement.
- (constraint) Render dort après 15 minutes et son réveil peut prendre environ une minute. WorkOS AuthKit en production demande des informations de facturation, même sur son quota gratuit. Utiliser uniquement des données fictives avec WorkOS staging pendant la validation.
- (question) Vérifier sur le compte web l’accès à Add custom MCP server, puis le cycle OAuth, le réveil Render et les appels Garmin avec les données autorisées au moment de la première story. Valider le fournisseur OAuth et la région proposés.
- (note) Git ignore tout fichier nommé .env. Le filtre est vérifié à la racine et en sous-dossier. Aucun chemin .env ne ressort de l’index ni de l’historique Git accessible.
- (decision) La revue impose le mode OAuth intégral, le challenge avec resource_metadata, le contrôle Origin et une configuration par environnement. La sonde publique reste opérationnelle pendant le premier déploiement fermé.
- (decision) La revue fixe les dates ISO inclusives, la non-duplication par activité et le sens de l’écart de sommeil. Le plafond de dépense Render repose sur l’offre Free et l’absence de moyen de paiement Render.
