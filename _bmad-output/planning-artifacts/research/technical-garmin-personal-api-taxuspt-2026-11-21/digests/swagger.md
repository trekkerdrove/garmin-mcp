### Activity search parameters

- Pagination/sort/favorites use `start`, `limit`, `sortBy`, `sortOrder`, `favorite` and `excludeChildren`. Defaults include newest-first, sorting by `startLocal`, favorite status `-1` for any, and excluding multisport child activities. The response is an array and the schema supplies no total-count field or hard page-size maximum. The SDK wrapper explicitly passes `limit=20`. [Official OpenAPI bundle](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js) · [Pinned SDK search and download](https://github.com/garmin/connect-personal-api-python/blob/958ef5883ba3b74f1b27a5c00dafc4e96351e723/src/garmin_personal_api/client.py#L242-L307)
- Classification/filtering uses `search` for name/description, `activityType` for a parent, `activitySubType` for its child, `eventType`, repeatable `excludedActivitySubType` and repeatable `requiredField`. The latter requires all supplied fields to have values. Inclusive `startDate` and `endDate` use activity local time. [Official OpenAPI bundle](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js)
- Metric filters use `minDistance`, `maxDistance`, `minDuration`, `maxDuration`, `minElapsedDuration`, `maxElapsedDuration`, `minElevation`, `maxElevation` and `minAvgPower`. Units are meters, seconds and watts as applicable. A location bounding box requires all of `upperLatitude`, `rightLongitude`, `lowerLatitude`, `leftLongitude`. Dive filters are `lowerMaxDepth`, `upperMaxDepth` in centimeters, `decoDive`, `minBottomTime`, `maxBottomTime` in seconds. [Official OpenAPI bundle](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js)

## Portability and scope distinctions

- **Training Effect and activity snapshots.** Detail `summaryDTO` contains `trainingEffect`, `anaerobicTrainingEffect`, classification strings/label and `activityTrainingLoad`. Search summarizes those concepts in a different schema, including `aerobicTrainingEffect`. Activity detail also documents `functionalThresholdPower`, `directFunctionalThresholdPower`, `lactateThresholdHeartRate` and `lactateThresholdSpeed` in m/s. These are activity snapshots. Taxuspt's cycling FTP and lactate-threshold tools read account-level estimates/history, for which Swagger supplies no dedicated operation. `HeartRateZonesDTO.lactateThresholdHeartRateUsed` describes a configured zone input. [Official OpenAPI bundle](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js) · [Taxuspt training tools](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp/training.py#L770-L812) · [Taxuspt FTP and threshold tools](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp/training.py#L1082-L1225)
- **Activity-associated workout steps and exercise sets.** `ActivityWorkoutDTO.steps[]` covers prescribed steps with repeat references, conditions, custom target values and an exercise weight in kg regardless of display preference. Activity search `summarizedExerciseSets[]` covers grouped reps, volume, duration and set counts. Taxuspt's exercise-set tool reads a recorded per-set resource, and its standalone workout tools read or modify the workout library. Neither surface has a dedicated Personal API operation. [Official OpenAPI bundle](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js) · [Taxuspt exercise-set tool](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp/activity_management.py#L928-L945) · [Taxuspt workout library tools](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp/workouts.py)
- **Respiration.** The V2 daily summary's `respiration` contains daily avg/min/max/latest values and timestamp. `wellnessChronology` lists the wellness measurement window and total duration. Sleep also has overnight avg/min/max. Daily respiration summaries/trends can be mapped to available per-day fields with changed payload shape. A raw daily respiration waveform is outside the documented schemas. [Official OpenAPI bundle](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js) · [Taxuspt raw/summary respiration tools](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp/health_wellness.py#L1402-L1449) · [Taxuspt trend](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp/training.py#L1753-L1820)
- **User identity and activity types.** Settings `displayName` supports a display-name feature and `measurementSystem` supports unit preferences. The schema contains no full name or complete social profile. Detail `metadataDTO.userInfoDto.fullname` and search `ownerFullName` are possible activity-dependent fallbacks, subject to owner identity and field availability. The official activity types response supplies only `key` and `parent`. Taxuspt's tool exposes IDs, display names, and visibility, which are missing from that simplified response. [Official OpenAPI bundle](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js) · [Taxuspt user profile tools](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp/user_profile.py#L119-L186) · [Taxuspt activity types tool](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp/activity_management.py#L1238-L1267)
- **Health payloads.** The documented daily and range sleep result type includes sleep stages as duration totals, sleep and nap windows, score data, sleep need and sleep alignment. Raw stage timelines are absent from this DTO. V2 summaries nest movement, calories, heart rate, intensity, stress, Body Battery, hydration, respiration, pulse ox and jet lag. Weight entries include composition fields such as BMI, fat, water, bone/muscle mass and metabolic age. Field coverage can vary with source data, and schemas for overlapping routes are distinct. [Official OpenAPI bundle](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js)
- **Archive and derived data.** Garmin documents an original-file archive. The SDK returns raw ZIP bytes and accepts `application/zip`, `application/x-zip-compressed` or octet-stream. Taxuspt exposes FIT, GPX, TCX and CSV as request formats. An official-only implementation can expose original downloads and, where file content permits, local conversions and FIT-derived analytics as separate capabilities. Actual archived formats, data completeness and parity require representative files. [Official OpenAPI bundle](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js) · [SDK download](https://github.com/garmin/connect-personal-api-python/blob/958ef5883ba3b74f1b27a5c00dafc4e96351e723/src/garmin_personal_api/client.py#L296-L307) · [Taxuspt download contract](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/README.md#activity-file-downloads)

## Features enabled by the published contract

These are recommendations inferred from the contract and pinned Taxuspt signatures.

- Add an advanced activity search with native filters and parent/subtype discovery. Taxuspt's general date search exposes dates, a type, page and page size. Garmin's search adds server-side names/descriptions, favorite/race filters, sorting, multisport controls, numeric thresholds, location and dive filters. [Official OpenAPI bundle](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js) · [Taxuspt date search](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp/activity_management.py#L175-L216)
- Expose workouts performed during a selected activity and structured wellness sessions by interval. Treat these as separate entities from the standalone workout library and daily health summaries. The wellness session schema includes timestamps, notes, session metrics, time in zones and recording-device metadata when present. [Official OpenAPI bundle](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js) · [Pinned Taxuspt source](https://github.com/Taxuspt/garmin_mcp/tree/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp)
- Expose historical effective weight goals and goal ranges separately from measurements. Offer a range-backed, flat weight export and lightweight range health views using explicit date windows and missing-day semantics. Use direct HRV and VO₂ max range operations for corresponding trends, with an optional FIT-sport filter on VO₂ max. [Official OpenAPI bundle](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js) · [Taxuspt weight tools](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp/weight_management.py)
- Offer opt-in payload controls where useful. Garmin documents meal filtering and toggles for nutrition goals/data/media, configurable Body Battery sampling, default zone generation, Fitness Age lookback and reduced/analysis options for cycle day view. [Official OpenAPI bundle](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js)

## Implementation boundaries

- Garmin documents account-owned personal use. User creates a key, which can expire after 30, 90, 180 days or one year. Java can POST `/personalapitoken-service/personal-api/personal-api-key/token` with `Authorization: ApiKey …`, then send `Authorization: Bearer …` on GET. The official SDK reads raw token text and JWT expiration. The FAQ states token lifetime is the shorter of 24 hours and the key's remaining lifetime. Exchange the key again for renewal. [Garmin Personal API FAQ](https://developer.garmin.com/gc-developer-program/personal/personal-faq/) · [Pinned SDK authentication](https://github.com/garmin/connect-personal-api-python/blob/958ef5883ba3b74f1b27a5c00dafc4e96351e723/src/garmin_personal_api/auth.py)
- Build contract fixtures around dates, arrays and wrapper objects, HTTP 204 on HRV, optional/variable fields, and source-dependent units. Document range caps by operation and keep implementation-specific batching separate from Garmin's published limits. The published sources used here give no quota or general rate-limit numbers. Live authorization, account/device availability, response fidelity and undocumented limits remain unverified.
