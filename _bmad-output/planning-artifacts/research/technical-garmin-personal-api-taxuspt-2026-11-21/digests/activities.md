Exact denotes the same core capability with documented inputs/data and ordinary projection. Derived requires Java pagination, decoding or computation on documented data. Partial denotes a meaningful officially sourced subset with a specific gap in the original behavior. Unsupported denotes no documented operation or data of the required meaning. Local denotes a feature implemented by the MCP host alone. These classifications concern contract feasibility and distinguish it from verified live parity.

## Official operations referenced below

| Search | `GET /activitylist-service/activities/search/activities` | `SummarizedActivityDTO[]`, offset `start`, `limit`, local start date inclusive, newest-first by default, excludes children by default, and separates parent `activityType` from child `activitySubType`. | Performed workouts | `GET /activity-service/activity/{activityId}/workouts` | `ActivityWorkoutDTO[]` with steps for workouts performed during an activity. ID is for the activity. Empty array when no workout was found. |

| Weight range | `GET /weight-service/weight/range/{startDate}/{endDate}?includeAll=true` | Local inclusive dates and `WeightRangeDTO` with latest and all daily records. `DateWeightDTO.weight` is documented in kilograms. |

## Activity management · 23 tools

Taxuspt builds curated summaries and uses additional private service endpoints for splits, weather, zones, exercise sets and writes. The pinned dependency shows the search/detail paths, the mobile gateway used for the single-day call, the independent count route and the independent formats. [Taxuspt activity tool implementations](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp/activity_management.py#L172-L1270), [dependency activity calls and fields](https://github.com/cyberjunky/python-garminconnect/blob/0.3.2/garminconnect/__init__.py#L1821-L1898), [dependency split, weather, zone, exercise and gear calls](https://github.com/cyberjunky/python-garminconnect/blob/0.3.2/garminconnect/__init__.py#L2329-L2428), [Garmin official schemas](https://developer.garmin.com/component---src-pages-gc-developer-program-personal-swagger-docs-js-7ced9e541531dfdd103f.js).

## FIT download and analysis · 5 tools

The official FIT Java SDK publishes `com.garmin:fit` and supports decoding recorded FIT activity messages. Use ZIP extraction and the SDK to inspect messages that are recorded in the source file. FIT outputs and heuristics still require Java logic and checks against reference fixtures. FIT file record completeness depends on the activity, recording device and sensors. The original download alone does not establish that its contents are FIT, or that conversion to Garmin's export formats is identical. [Taxuspt FIT implementation and tools](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp/activity_analysis.py), [FIT Java SDK](https://github.com/garmin/fit-java-sdk#install), [Garmin FIT overview](https://developer.garmin.com/fit/overview/), [official download wrapper](https://github.com/garmin/connect-personal-api-python/blob/958ef5883ba3b74f1b27a5c00dafc4e96351e723/src/garmin_personal_api/client.py#L296-L307).

| Registered tool | Result | Mapping and compatibility |
| --- | --- | --- |
| `get_activity_fit_messages` | Derived | Original ZIP plus local FIT decode. Preserve type selection, `include_records`, offset and limit, data-type formatting, unknown/developer fields, enum/raw values, and truncation metadata. Validate FIT extraction and support an explicit no-FIT outcome. |
| `get_activity_fit_data` | Derived | Original ZIP plus local FIT analysis for recorded sessions, laps, electronic shifts, cycling dynamics, power, VAM/climbs, grade, drift, temperature and HRV. Preserve multisport leg selection and missing-sensor behavior. Weight range supplies the 90-day weigh-in data for W/kg. Official weights are already in kg. Legacy Taxuspt divides grams by 1,000, so copying that conversion is incorrect. Taxuspt selects `(calendarDate, weight)` lexicographically, which chooses the heaviest reading on the latest date when weights differ that day. Choose deliberately between that parity and the chronologically latest reading. |
| `get_power_duration_curve` | Derived | Search for recent entries of the requested sport, then download Original per activity and port the local 1 Hz timing, gap and sliding-window algorithm. Preserve the 50-activity limit, winner ID/date, skipped-file handling and 20-minute × 0.95 estimate. Search also documents `maxAvgPower_{5,30,60,300,600,1200,3600}`, matching all seven durations and permitting a lighter alternative. Garmin does not document that those fields replicate Taxuspt's treatment of pauses and missing power. |
| `download_activity_file` | Partial | Original ZIP supports saving the original FIT member when one exists. Taxuspt also accepts GPX, TCX and splits CSV, handled by separate private export routes. Conversion could yield local files of those types but would be a different export implementation. Its `output_dir`, environment and persisted-path fallback are local decisions. |
| `set_fit_download_dir` | Local | Persists the local default path consumed by download. No Garmin call. Consider whether server-side file access and local configuration are suitable for the target MCP deployment. |

Useful test cases from the Taxuspt code are multisport files, embedded or absent developer fields, smart-recording gaps versus stopped periods, damaged or non-FIT original downloads, missing sensors and power, empty exercise sets, and workouts or activities with no expected metadata. [Taxuspt activity analysis tests](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/tests/integration/test_activity_analysis_tools.py), [Taxuspt activity management tests](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/tests/integration/test_activity_management_tools.py).

## Delivery implications

- Implement the documented activity Search and Detail integrations first. Preserve explicit pagination/filter semantics and field units. The official Types and Performed workouts reads give consumers usable distinct contracts. The original ZIP read is independently supported. [Garmin Swagger](https://developer.garmin.com/gc-developer-program/personal/swagger-docs), [official SDK activity implementation](https://github.com/garmin/connect-personal-api-python/blob/958ef5883ba3b74f1b27a5c00dafc4e96351e723/src/garmin_personal_api/client.py#L242-L315).
- Add bounded ZIP decoding and FIT projections with recorded/manual/imported/multisport fixtures before advertising analysis parity. Add exact per-activity power calculations only if the expected behavior requires Taxuspt's PDC algorithm. Local timetable, GPX or FIT generation may remain useful as standalone features where the caller asks for a file. [Taxuspt FIT analysis behavior](https://github.com/Taxuspt/garmin_mcp/blob/a2ca5fcac34524b83814fe2fcf3d479f8a75983f/src/garmin_mcp/activity_analysis.py), [Garmin FIT Java SDK](https://github.com/garmin/fit-java-sdk).
- Runtime verification remains open for account entitlements, available data and sensor fields, inclusion rules for same-day and count views, page-size ceilings, and equivalence of private payloads. No personal API requests were made. [Garmin Personal API FAQ](https://developer.garmin.com/gc-developer-program/personal/personal-faq/), [Garmin contract](https://developer.garmin.com/gc-developer-program/personal/swagger-docs).
